    • 任务转换的主要步骤

    1. 保存当前任务的现场：当任务被打断（比如系统Tick中断或主动让出CPU），单片机硬件会自动把PC、PSR、R0-R3、R12、LR这些寄存器压入当前任务的栈中。然后，软件（即<代码>xPortPendSVHandler中断服务函数）会继续把R4-R11等其他寄存器也保存到该任务的私有栈中，最后把栈指针（SP）的值保存到该任务的任务控制块（TCB）里。

    2. 恢复新任务的现场：调度器找出下一个要运行的任务，从它的TCB中取出上次保存的SP，然后用这个SP从栈里弹出之前保存的所有寄存器值（包括PC）。最后，当CPU执行到弹出的PC地址时，就恢复运行新任务了。

    有几种情况会导致任务切换？

    主要有4种情况：

    1. 任务主动阻塞：调用<代码>vTaskDelay()、等待队列/信号量等。

    2. 任务主动让出CPU：调用<代码>taskYIELD()。

    3. 时间片用完：在系统Tick中断中，发现当前同优先级任务运行时间耗尽。

    4. 更高优先级任务就绪：例如，在中断服务程序（ISR）中释放了一个信号量，导致等待该信号量的高优先级任务变为就绪态，中断退出后就会立即切换过去。

    不同类型的任务应该给怎样的优先级？

    实战经验法则 这是避免系统“卡死”的黄金法则。高优先级任务在完成其关键工作后，必须通过调用 vTaskDelay()、xQueueReceive() 等 API 进入阻塞状态，主动释放 CPU 使用权。如果高优先级任务是一个无限循环且不进入阻塞态，那么所有比它优先级低的任务将永远得不到执行（即“任务饥饿”）。

  • 警惕优先级反转 当高优先级任务等待一个由低优先级任务持有的共享资源（如互斥量）时，一个中等优先级的任务可能会抢占低优先级任务，导致高优先级任务被间接阻塞。 解决方案：务必使用支持优先级继承的互斥量（通过 xSemaphoreCreateMutex() 创建），而不是普通的信号量来保护共享资源。

  • 中断优先级永远高于任务优先级任何硬件中断都能抢占任何任务的执行。中断服务程序（ISR）应尽量保持简短，只做最紧急的处理（如置位标志、发送通知），复杂的逻辑应交给高优先级的任务来处理。

    什么是优先级继承

    “优先级继承”是一种用来解决优先级反转问题的机制，在FreeRTOS中通过互斥量（Mutex）实现。

    1. 先看“优先级反转”是什么问题

    假设有三个任务：

    • 高优先级任务H：需要访问共享资源（比如一个保护串口打印的互斥量）。

    • 中优先级任务M：纯计算任务，不访问该资源。

    • 低优先级任务L：已经获得了那个互斥量，正在使用共享资源。

    正常情况下，当H等待L释放互斥量时，L应该尽快执行完。但如果此时中优先级任务M就绪（比如有数据要处理），由于M的优先级高于L，调度器会抢占L，让M先跑。结果就是：H被L阻塞，L又被M抢占，导致高优先级任务H迟迟得不到执行，反而被中优先级任务M“间接”阻塞——这就叫优先级反转。

    2. 优先级继承如何解决？

    FreeRTOS的互斥量内置了优先级继承逻辑：

    • 当高优先级任务H尝试获取被低优先级任务L持有的互斥量而进入阻塞时，内核会临时将L的优先级提升到与H相同（即继承H的优先级）。

    • 此时L的优先级变高了，就不会被中优先级任务M抢占，可以快速运行并释放互斥量。

    • L释放互斥量后，内核自动将L的优先级恢复为原来的低优先级。随后H成功获得互斥量，继续运行。

    简单比喻：低优先级任务“借”了高优先级任务的优先级，以确保自己不被中间人打扰，能尽快交还资源。

    3. 在FreeRTOS中的实际使用

    • 需要使用互斥量（xSemaphoreCreateMutex()），而不是二值信号量。二值信号量没有优先级继承功能，可能导致反转。

    • 需要使能配置宏 configUSE_MUTEXES 为 1。

    • 优先级继承不能完全消除阻塞（H依然要等L释放资源），但它能保证阻塞时间只受L自身执行时间影响，而不再被不相关的M任务无限拉长。

    注意：优先级继承不能解决“死锁”问题，而且只能缓解一次嵌套的情况。更严格的机制叫“优先级天花板”，但FreeRTOS默认只提供优先级继承。

    以上就是优先级继承的作用和原理。

    如果就绪态有多个同优先级的任务，哪个先进行？

    在FreeRTOS中，如果多个同优先级的任务同时处于就绪态，调度器会从该优先级的就绪链表中按顺序选取任务来执行。

    具体规则如下：

    1. 初始顺序：任务创建时会默认添加到就绪链表的尾部。因此，如果没有其他干扰，先创建的任务会先获得CPU。

    2. 时间片轮询过程：

      • 当前任务执行完一个时间片（或主动让出CPU，如调用taskYIELD()）后，调度器会将其移动到就绪链表的尾部。

      • 然后将原链表中的下一个任务（即原来的头部第二个任务）移到头部，并开始执行它。

      • 这样循环往复，实现“轮转”。

    3. 抢占后的行为：如果一个任务被高优先级任务抢占，当高优先级任务结束后，被抢占的任务会继续待在链表头部（它没有被移到最后），从而得以继续运行剩余的时间片。

    总结一句话：同优先级就绪任务的执行顺序是基于它们在就绪链表中的位置，按照 “先来先服务 + 时间片轮转” 的方式决定——初始时先创建的先运行，之后每个任务轮流获得时间片。

    你可以把这个链表想象成一个环形队列，每次任务运行完时间片或主动让出，就被放到队尾，然后队首的下一个任务出队运行。
